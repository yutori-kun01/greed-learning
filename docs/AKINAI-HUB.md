# Akinai hub との連携

Akinai hub（販売・メルマガ・決済の基盤）で講座を売り、購入者がこの会員サイトでそのまま受講できるようにする設定です。

- 購入者は「**Akinai hubでログイン**」を押し、購入時のメールアドレスに届く認証コードでログインします。パスワードは不要です。
- Akinai hubで入金済みになった注文の商品に紐づく講座が開放されます。返金・利用停止にすると閉じます。
- 既存の会員（メール/パスワード登録済み）が同じメールアドレスで購入した場合も、その会員のまま開放されます。
- サインアップのパスコードは、Akinai hubで何か購入済みの人には不要です（購入が招待の代わり）。

## 仕組み

| 経路 | 内容 |
| --- | --- |
| ログイン | OpenID Connect（認可コード＋PKCE）。Akinai hubがメールの本人確認を行い、ID トークンを署名して渡します |
| 購入の反映 | Akinai hubが署名付きWebhook（`/api/webhooks/akinai`）で購入・停止を通知します。届かなかった場合も、次回ログイン時の購入一覧（entitlements）で補正されます |
| 判定 | 講座に設定した商品のいずれかが、ログイン中のメールアドレスで有効なら開放。プラン・個別付与（enrollment）による開放はこれまでどおり併用できます |

## 設定手順

1. Akinai hub の管理画面 → **連携・ライセンス** → **連携アプリを追加**
   - リダイレクトURI: `https://<会員サイトのURL>/api/auth/callback/akinai`
   - Webhook URL: `https://<会員サイトのURL>/api/webhooks/akinai`
   - 会員サイトに渡す商品: 講座として売る商品を選ぶ（未選択なら全商品）
   - 作成時に表示される **Issuer / クライアントID / クライアントシークレット** を控える（シークレットは再表示されません。紛失時は再発行）
2. この会員サイトのシークレットに設定（GitHub ActionsのSecretsに登録すればデプロイ時に同期されます）
   - `AKINAI_ISSUER` = Akinai hubのURL（例 `https://store.example.com`）
   - `AKINAI_CLIENT_ID` / `AKINAI_CLIENT_SECRET`
3. D1マイグレーション `0017_akinai_hub.sql` を適用（通常のデプロイ手順で適用されます）
4. 管理画面 → 講座の編集 → 「Akinai hubで販売」で商品にチェックし、購入ページのURLを入れて保存
5. Akinai hubの連携アプリ一覧で「Webhookテスト」を押し、成功することを確認

## 注意

- 判定はメールアドレスで行います。購入時と違うアドレスで登録した会員には開放されません（会員側でメールアドレスを変更するか、管理画面から個別付与してください）。
- Akinai hubの `AUTH_SECRET` を変更すると、クライアントシークレットも変わります。会員サイト側の `AKINAI_CLIENT_SECRET` を再設定してください。
- 講座の「Akinai hubで販売」欄は連携設定がある時だけ表示されます。設定を外しても、講座に保存した商品の紐づけは消えません（講座はロックされたままになります）。
